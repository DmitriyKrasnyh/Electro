# Электромонтаж

Приложение для бригады электромонтажников: задачи по системам, статусы, блокировки, фото, планы этажей.

- `frontend/`: приложение на React, Vite, TypeScript и Tailwind
- `supabase/`: SQL-файлы для базы в Supabase (таблицы, права, тестовые данные)

Данные, вход и файлы хранятся в облачной базе Supabase. Свой сервер запускать не нужно.

## Что нужно установить

**Node.js LTS**, версия 20.6 или новее: https://nodejs.org. Проверка: `node -v`.

## Настройка Supabase (один раз)

Всё делается в панели проекта на https://supabase.com/dashboard.

### 1. Запретить самостоятельную регистрацию

Обязательный шаг. Адрес проекта и публичный ключ видны в приложении любому, кто его открыл. Пока регистрация открыта, кто угодно может завести себе вход и увидеть все данные.

**Authentication → Sign In / Providers**, выключите **Allow new users to sign up** и сохраните.

### 2. Создать таблицы

**SQL Editor → New query**. Вставьте всё содержимое файла `supabase\01_schema.sql` и нажмите **Run**. Должно появиться «Success. No rows returned».

Файл создаёт таблицы, права доступа и хранилища для фото и планов. Повторный запуск ничего не ломает.

Так же, отдельными запросами, примените:

- `supabase\04_passwords.sql`: администратор, который может задавать пароли бригаде;
- `supabase\05_cable_journal.sql`: кабельный журнал;
- `supabase\07_room_points.sql`: помещения на планах этажей;
- `supabase\08_states_chains_documents_grounding.sql`: состояния кабелей, цепочки задач, документы объекта и заземление.

### 3. Добавить пользователей бригады

**Authentication → Users → Add user → Create new user**:

- **Email**: логин и `@brigada.local`, например `ivanov@brigada.local`. Монтажник при входе вводит только `ivanov`. Логин: строчные латинские буквы и цифры.
- **Password**: пароль, минимум 6 символов.
- Галочка **Auto Confirm User** должна стоять. Писем этот адрес не получает.

Имя на экранах сначала совпадает с логином. Поменять его можно в **Table Editor → profiles**, колонка `name`.

### 4. Тестовые данные (по желанию)

Для проверки приложения: **SQL Editor → New query** → содержимое `supabase\02_test_data.sql` → **Run**. Создаются объект, 3 этажа, 9 помещений и 15 задач. Если перед этим завести пользователей `ivanov`, `petrov` и `sidorov`, задачи сразу получат исполнителей, а люди имена. Повторный запуск ничего не задвоит.

## Запуск приложения на Windows

Все команды для PowerShell, пути от корня проекта.

Перейти в папку приложения:

```powershell
cd frontend
```

Создать файл настроек:

```powershell
copy .env.example .env
```

Откройте `frontend\.env` и подставьте адрес проекта и публичный ключ (начинается с `sb_publishable_`). Оба значения есть в панели Supabase: кнопка **Connect** вверху или **Project Settings → API Keys**. Секретный ключ (`sb_secret_`) сюда не ставьте никогда.

Установить зависимости:

```powershell
npm install
```

Запустить приложение. Окно оставьте открытым:

```powershell
npm run dev
```

Откройте http://localhost:5173 и войдите логином (например, `ivanov`) и паролем из шага 3.

Если вы поменяли `.env`, перезапустите `npm run dev` (Ctrl+C и снова команда).

## Как проверить установку и работу без сети

Правки сохраняются на устройстве и уходят на сервер сами, это работает и в `npm run dev`. А вот запуск без сети и установка на экран есть только в собранной версии.

В папке `frontend` соберите приложение:

```powershell
npm run build
```

Запустите собранную версию. Окно оставьте открытым:

```powershell
npm run preview
```

Откройте http://localhost:4173, войдите и один раз обновите страницу. Дальше можно проверять:

1. Отключите интернет на компьютере (Wi-Fi или кабель) и обновите страницу: приложение откроется без сети.
2. Поменяйте статус задачи: вверху появится «Нет связи · 1 изменение ждёт отправки».
3. Включите интернет: примерно через 15 секунд изменение уйдёт на сервер само.

Установить приложение можно кнопкой «Установить на экран телефона» внизу главной, если браузер её предлагает, или через меню браузера.

После новой сборки открытое приложение получит обновление при следующем запуске.

## Планы этажей

- **Загрузка.** На экране «Этажи и помещения» у каждого этажа есть кнопка «Загрузить план». Подходят PDF, JPG, PNG и WebP до 50 МБ. Из PDF показывается только первая страница.
- **Просмотр.** Главный экран → «Планы этажей». Масштаб меняется щипком, кнопками «+» и «−», на ноутбуке колесом мыши. План перетаскивается пальцем или мышью.
- **Точки задач.** Цвет точки показывает статус задачи, красное кольцо означает блокировку. Нажатие на точку открывает её карточку. Внизу можно оставить только одну систему.
- **Новая задача.** Нажмите на план в нужном месте, затем «Создать задачу».
- **Точка для существующей задачи.** В карточке задачи блок «Точка на плане»: «Поставить точку», «Показать», «Переставить». Если задачу перенести на другой этаж, точка снимается.
- **Без сети.** Каждое устройство само скачивает файлы планов и хранит их у себя. План новой версии уходит на другие устройства при следующей синхронизации. Большие планы скачиваются и по мобильному интернету, поэтому файлы лучше делать не слишком тяжёлыми.

- **Помещения на плане.** На экране «Этажи и помещения» у каждого помещения есть кнопка с меткой. Она открывает план, где нужно нажать на место помещения и сохранить. После этого на плане виден номер помещения, а метка у помещения становится тёмной. Переставить точку можно той же кнопкой.
- **Из кабельного журнала.** У группы линий, помещение которой указано на плане, есть кнопка с меткой. Она открывает план, приближенный к этому помещению, номер помещения подсвечен.

Точки хранятся в процентах от листа. Если заменить план чертежом другого формата, они останутся на тех же местах листа, но могут оказаться не там на чертеже.

## Как работает обмен с сервером

- **Очередь.** Экраны работают только с базой на устройстве. Каждое действие сразу сохраняется там и встаёт в очередь отправки, порядок действий сохраняется. Посмотреть очередь можно на экране «Отправка изменений».
- **Когда идёт обмен.** При запуске, при появлении сети, после каждой правки и по таймеру, пока приложение открыто. Закрытое приложение ничего не отправляет: очередь уйдёт при следующем запуске.
- **Конфликты.** Побеждает правка, сделанная позже по часам устройства, причём отдельно для каждого поля. Если двое поменяли разные поля одной задачи, сохранятся обе правки. В истории видны все правки по времени. Чек-лист считается одним полем.
- **Отказ сервера.** Если сервер не принял изменение (например, задачу удалили в панели Supabase), оно отмечается красным на экране «Отправка изменений», остальная очередь идёт дальше. Изменение можно повторить или удалить.
- **Выход.** Выход стирает данные с устройства, поэтому при неотправленных изменениях он запрещён.
- **Без сети доступно** всё, кроме первого входа на новом устройстве. Из фото других монтажников без сети открываются только те, что уже просматривались на этом устройстве.

## Кабельный журнал

Главный экран → «Кабельный журнал». В нём линии из проектных журналов: маркировка, трасса, марка кабеля и длина по проекту.

- **Состояние кабеля:** не проведён → проведён → выведен в подрозетник. Отметка «Выведен в подрозетник» сразу ставит и «Проведён», а снятие «Проведён» снимает и её.
- **Отметки.** Сверху выбирают, что отмечают: «Проведён», «Выведен в подрозетник», «Промаркирован», «Оконечен» или «Проверен». Затем нажимают на линии. Повторное нажатие снимает отметку. Под линией видно, кто и когда её отметил, и текущее состояние кабеля.
- **Помещение целиком.** Кнопка «Отметить все» у группы ставит выбранную отметку всем её линиям сразу.
- **Поиск и фильтры.** Поиск по маркировке или помещению (например, `i64`), фильтр по системе и этажу. Сводка показывает, сколько линий и метров уже отмечено.
- **Без сети** отметки ставятся так же и уходят на сервер сами, как правки задач.
- **Исполнительная документация.** Кнопка «Скачать Excel» внизу экрана. В файле:
  - по листу на систему в форме проектного журнала;
  - колонки «Проложен» заполнены у отмеченных линий. Длина берётся проектная: монтажники её не измеряют;
  - лист «Ход работ», где по каждой линии указано, кто и когда поставил каждую отметку.
- **Сами линии** (маркировку, трассу, длину) из приложения поменять нельзя. Их загружает администратор SQL-файлом, как `supabase\06_object_prechistenskaya.sql`. Исправить отдельную линию можно в **Table Editor → cable_lines**.

## Цепочки работ

В карточке задачи блок «Цепочка работ»:

- **Сначала нужно сделать.** Задача, которую нужно сдать раньше этой. Пока она не сдана, в списках у задачи надпись «Ждёт: …», а в карточке «Ждёт: предыдущая задача ещё не сдана». Когда предыдущую сдают, появляется «можно начинать».
- **После неё.** Задачи, которые ждут эту.
- **Создать следующую задачу.** Новая задача сразу получает ту же систему, этаж и помещение и ждёт текущую. Так цепочку удобно собирать прямо на объекте: проложить кабель → смонтировать камеру → настроить.

Задачу нельзя поставить в ожидание самой себя или задачи, которая сама её ждёт: такие варианты в списке не показываются.

## Документы

Главный экран → «Документы». Проект, альбомы, схемы в PDF.

- **Просмотр.** Документ листается по страницам, страница увеличивается щипком и кнопками, как план этажа. Кнопка «Сохранить файл» сохраняет PDF на телефон, например чтобы открыть его в другой программе.
- **Без сети.** Документ скачивается на устройство при первом открытии, дальше открывается и без связи. Кнопка «Убрать с устройства» освобождает место, документ останется в списке.
- **Добавляет и удаляет** документы только администратор, со связью. PDF до 50 МБ.

## Заземление

«Заземление» есть в списке систем, как СКУД или видеонаблюдение: для задач и кабельного журнала.

Главный экран → «Замеры заземления» (или кнопка в списке задач заземления):

- **Новый замер:** что мерили, сопротивление в омах, норма (по проекту не более 4 Ом), этаж и помещение, прибор, комментарий. Прибор запоминается на устройстве. Дробные числа можно вводить и с запятой.
- **Превышение нормы** выделено красным, вверху видно, сколько таких замеров.
- **Протокол.** Кнопка «Скачать Excel» выгружает все замеры одной таблицей с отметкой о соответствии.
- **Ошибочный замер** удаляет администратор, после этого замер записывают заново.

## Пароли

Для смены пароля нужна связь с сервером.

- **Свой пароль.** Главный экран → внизу «Пароль» → блок «Мой пароль». Нужно ввести текущий пароль и дважды новый, не короче 8 символов.
- **Забытый пароль.** Администратор на том же экране, в блоке «Пароль для члена бригады», выбирает человека и задаёт ему новый пароль. Старый перестаёт работать, на своих устройствах человек входит заново. Неотправленные изменения на его устройствах при этом не пропадают.
- **Кто администратор.** Отметка `is_admin` в **Table Editor → profiles**. Поставить её можно только там, из приложения нельзя.
- **Стартовые пароли** аккаунтов бригады лежат в `supabase\.env`. Попросите каждого сменить свой пароль после первого входа.

## Права в базе

- Без входа не видно ничего, ни записей, ни файлов.
- Монтажники читают всё, создают и меняют этажи, помещения и задачи, добавляют фото и записи истории.
- Удалять из приложения нельзя ничего. Историю и фото нельзя и менять. Удаляет администратор в панели Supabase (**Table Editor**).
- Свой логин поменять нельзя, своё имя можно.
- Задавать пароли другим может только администратор.
- Документы объекта добавляет и удаляет только администратор. Удалять замеры заземления и задачи тоже может только он.

## Как подготовить настоящий объект

1. Если в базе были тестовые данные, сотрите их (раздел «Как начать базу заново»).
2. Создайте объект: **Table Editor → objects → Insert → Insert row**, заполните `name` и при желании `address`. Остальные поля заполнятся сами.

   Для объекта на Пречистинской набережной это уже сделано файлом `supabase\06_object_prechistenskaya.sql`. Он создаёт объект, этажи «1 этаж» и «Антресоль», помещения по экспликациям и 142 линии кабельного журнала.
3. Заведите пользователей бригады (шаг 3 настройки).
4. В приложении на главном экране, внизу, откройте «Этажи и помещения» и добавьте их. Новый этаж встаёт в конец списка, поэтому добавляйте этажи в том порядке, в каком они должны идти. Изменить порядок потом можно в **Table Editor → floors**, колонка `order`.

## Как проверить на телефоне

Телефон и компьютер должны быть в одной сети Wi-Fi. База в облаке, поэтому настраивать на компьютере нужно только само приложение.

В папке `frontend` запустите приложение с доступом из сети:

```powershell
npm run dev -- --host
```

В выводе команды будет строка `Network: http://192.168.…:5173`. Откройте этот адрес на телефоне. Если Windows спросит про брандмауэр, разрешите доступ для частных сетей.

Так можно проверить экраны, камеру и очередь правок. Установка на экран и запуск без сети на телефоне работают только по HTTPS, это будет после размещения приложения в интернете (Render).

## Бесплатный тариф Supabase

- Если к проекту неделю никто не обращается, он засыпает. Разбудить его можно кнопкой в панели Supabase. Пока бригада работает каждый день, это не грозит.
- Хранилище файлов — 1 ГБ на все фото и планы. Сжатое фото весит примерно 0,3 МБ. Сколько занято, видно в панели в разделе **Usage**.
- Заменённые планы остаются в хранилище: **Storage → plans**. Старые версии можно удалить там вручную.

## Частые проблемы

- **PowerShell пишет, что выполнение сценариев отключено** (при запуске `npm`). Выполните те же команды в «Командной строке» (cmd): `cd`, `copy` и `npm` работают там так же.
- **«Неверный логин или пароль», хотя всё верно.** Проверьте в **Authentication → Users**, что адрес пользователя заканчивается на `@brigada.local` и у него нет пометки «Waiting for verification». Если она есть, удалите пользователя и создайте снова с галочкой **Auto Confirm User**.
- **Приложение пишет «Нет связи», хотя интернет есть.** Проверьте адрес и ключ в `frontend\.env` и перезапустите `npm run dev`. Ещё проект мог заснуть, см. раздел про бесплатный тариф.
- **Ошибка `Cannot find module` с упоминанием `rolldown` или `oxide` после переноса проекта с другого компьютера.** Удалите папку `frontend\node_modules` и снова выполните `npm install`. Папку `node_modules` между компьютерами не копируйте.

## Как начать базу заново

Пользователи при этом остаются, а задачи, этажи, фото и история удаляются **навсегда**:

1. **SQL Editor → New query** → содержимое `supabase\03_clear_data.sql` → **Run**.
2. **Storage**: откройте `photos`, выделите все файлы и удалите. То же для `plans`.

Телефоны уберут стёртые данные у себя сами, в течение 10 минут после появления связи.

## Как менять структуру базы

Структуру описывают SQL-файлы в папке `supabase`, они хранятся в проекте. Каждое изменение пишется новым файлом со следующим номером (`04_…sql`) и запускается в **SQL Editor**. Если поменять таблицу прямо в панели Supabase, запишите это изменение и в новый файл, иначе в другом проекте его не будет.

## Запуск на macOS

Отличия от команд выше: `cp` вместо `copy`, пути через `/` вместо `\`.
